# DevPilot Agent 运行规则（硬性）

本文件在每次会话开始时自动加载。以下规则优先级高于模型自身判断；违反即视为执行失败，不允许以「任务看起来简单」为由绕过。

## 1. 斜杠命令路由

- 用户消息以 `/` 开头时，必须先在已安装技能中匹配同名命令，并严格按对应技能的 SKILL.md 执行。
- 匹配到技能后，按 SKILL.md 规定的步骤与输出约定执行，禁止抛开技能内容自行发挥或仅凭常识作答。
- 技能命令名会被规范化为小写 + 下划线：`g5-deploy` 技能对应的命令是 `/g5_deploy`。
- 若命令无法匹配任何技能，如实告知「未找到该技能命令」并列出可用技能命令，不要模拟执行、也不要转成普通对话自行处理。

## 2. 开发需求路由（G 链）

任何新功能 / 新服务 / 改动 / 修复类需求，一律从 G1 需求探索（explore）进入完整流水线：

> explore(G1 需求探索) → prd(G2 需求分析) → plan(G3 计划拆解) → dev(开发执行) → review(代码审查) → test(G4 测试验证) → g5-deploy(G5 提交部署)

- 禁止跳过阶段直接写代码，除非用户明确要求跳过（此时须在回复中复述用户要求的跳过范围）。
- 各阶段的角色、产出物与验收标准以对应技能的 SKILL.md 为准，不要自行发明流程。
- 纯问答 / 咨询类消息（不产生代码改动）不需要进入 G 链。

## 3. 部署执行事实

- 本容器没有 docker CLI；部署一律通过 exec 调用 `bash /opt/devpilot/cicd/service-deploy/feishu-deploy-handler.sh "<完整命令>"`，由处理器内部自动判定：已配置 SSH 受控通道（DEPLOY_SSH_HOST）时自动转发宿主机执行并返回真实结果；未配置时构建/部署类命令被拦截属于预期行为。
- 两种情况下都**禁止**自行执行 ssh、绕过处理器、编造部署结论或改用自己的方案；输出原样回贴（含 `[ssh]` 转发标记或拦截提示）。

## 4. 技能输出纪律

- 技能规定的输出格式 / 卡片 / 验收文案按原样输出，不要自行改写、删减或「美化」。
- 技能内命令执行失败时，原样反馈错误信息与技能规定的下一步动作，不要静默降级成自己临场想出的替代方案。
